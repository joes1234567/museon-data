鋼構工程暨材料買賣雙公司營運管理系統 — 系統規劃文件

版本：v1.0（Discussion 階段，依 2026-07-24 訪談紀錄產出） 日期：2026-07-28 文件用途：系統規劃評估，供比稿／內部討論使用，不含開發費用與合約條款 資料來源：《鋼構工程暨材料買賣營運管理系統需求訪談會議紀錄》（2026-07-24）+ 逐字稿交叉核對

① 專案摘要

一句話描述 建立一套雙公司（鋼構工程公司＋既有材料買賣公司）共用平台、財務與資料互相隔離的 Web 營運管理系統，串聯「工程接案 → 材料供應 → 施工回報 → 階段性請款 → 財務結算」的完整閉環，並涵蓋鋼材裁切餘料庫存、人事薪資與文件管理。

業務背景 客戶目前已有一家持續營運的材料買賣公司（採購、拆圖、訂料、出貨、庫存）；預計 2026 年 8 月另成立鋼構工程公司承接工程案件。兩家公司同一經營者管理、營運流程互相關聯，但因稅務、股東交代與公司治理，財務與資料須明確分開。客戶希望單一平台快速切換兩家公司，避免公司擴張後才導入系統造成的重複輸入與流程重工。

使用者角色

角色 描述 主要操作
公司負責人／最高管理者 兩家公司共同經營者 切換公司、查看全部案件、財務、報表、審核結果
工程主管 工程公司 查看進度、審核施工報告、管理現場事項
專案／工程人員 工程公司 回報進度、上傳施工報告與照片
材料／拆圖人員 材料公司 拆圖、整理材料尺寸數量、建立採購需求
採購人員 材料公司 建立採購單、追蹤到貨
倉儲／材料管理人員 材料公司 入庫、出庫、裁切、餘料、庫存管理
行政／人資人員 兩公司共用 員工資料、合約、請假、加班、文件管理
財務／會計人員 兩公司共用 收支、請款、薪資、憑證、損益報表
一般員工 兩公司共用 查閱授權文件、提交請假加班
外部會計／顧問 兩公司共用（唯讀） 依權限查看或匯出財務資料

各角色採最小權限設計，同一平台不可任意查看另一家公司或其他部門的敏感資料——這是本案與一般單一公司系統最大的差異，必須在資料層而非畫面層落實隔離。

目標與範圍邊界

  • ✅ 在範圍內：雙公司切換與資料隔離、工程專案管理、階段性請款鎖定、施工報告與照片、材料規格／裁切／餘料庫存、採購銷售、人事薪資、文件管理、財務損益報表
  • ❌ 明確排除（另案規劃）：未來加工廠完整 MES／生產排程、複雜 BOM 與製程管理、IoT 設備串接
  • ❌ v1 不做：原生 App（純響應式 Web）、AI 自動拆圖／自動估價、完整 ERP 總帳與稅務申報、複雜排班、自建主機房

規模假設（⚠️ 待客戶確認，見附錄待辦事項 A08）

  • 使用人數、預估案件量：訪談中未提供具體數字，需客戶提供（A08）
  • 公司數：2（工程公司＋材料公司），未來可能擴充加工廠（不計入本次範圍）
  • 資料量：長期累積施工照片＋合約掃描檔，屬中至大量非結構化文件儲存

② 功能需求

User Stories（節錄重點角色）

公司負責人 - 身為負責人，我需要在同一介面切換工程公司與材料公司，以便集中掌握兩邊營運而不用登入兩套系統 - 身為負責人，我需要查看合併管理檢視，以便掌握整體狀況，同時系統仍需保證不會混淆各自法定帳務

工程主管 - 身為工程主管，我需要審核每日施工報告與照片，以便確認現場進度真實可信 - 身為工程主管，我需要在請款節點被鎖定時看到警示，以便判斷是否需要例外授權

專案人員 - 身為專案人員，我需要用手機瀏覽器回報施工進度與上傳照片，以便不用回辦公室才能提交

拆圖／採購人員 - 身為拆圖人員，我需要依圖面產生材料需求表並轉為採購單，以便減少人工轉抄錯誤 - 身為倉儲人員，我需要記錄一支材料裁切後的實際使用量與剩餘量，以便餘料仍可被追蹤與再利用

財務人員 - 身為財務人員，我需要在收到前一階段款項前系統鎖定下一階段，以便落實「未收款不進下一階段」的內控要求 - 身為財務人員，我需要分別查看兩家公司的損益表，以便對股東與稅務清楚交代

核心業務流程（BDD 情境大綱）

流程 情境 摘要
工程接案 建立專案並設定階段 建立客戶、案場、合約，設定總金額、階段、請款條件；收取定金後啟動
階段性請款 未收款鎖定 前一階段款項未確認收到時，系統阻擋進入下一階段，除非有授權例外並留稽核紀錄
階段性請款 收款確認後解鎖 財務確認收款 → 系統自動解鎖下一階段 → 通知工程主管
材料供應 工程公司發出材料需求 工程公司建立材料需求 → 材料公司拆圖確認規格數量 → 產生採購單
材料供應 到貨入庫與出料 材料到貨驗收入庫 → 依工程需求出料 → 記錄實際使用量與剩餘量
裁切餘料 裁切追蹤 一支原料理論可切 N 片，實際使用 M 片，剩餘 (N-M) 片仍須成為可追蹤庫存項目，含規格、位置、可否再用
外部客戶銷售 一般進銷存 材料公司同時服務外部客戶，建立客戶訂單、查庫存或採購、出貨、應收帳款、對帳
施工報告 每日填報與審核 現場人員上傳紙本掃描/照片＋填寫當日工作內容 → 主管審核／退回補件 → 與工程里程碑連動；歷次版本不可覆蓋
人事簽約 新員工入職 建立員工基本資料 → 上傳勞動契約、工作守則、保密協議等文件 → 轉檔案管理模組 → 員工確認簽收
出勤管理 上班打卡與異動 每日記錄上班時間、下班時間 → 計算實際出勤時數 → 標記請假、加班異動
請假加班 員工申請到審核 員工提交請假單／加班單 → 主管審核 → 系統記錄 → 計入月度薪資計算
薪資計算 月末計薪 彙整當月出勤、請假、加班 → 依勞基法計算薪資 → 產生薪資明細單 → 產出 PDF 薪資單
薪資發放 薪資單簽收 員工查閱薪資單 → 簽收確認 → 留存紀錄（勞檢備查）
文件管理 紙本＋系統雙軌 合約、施工報告、薪資憑證、請假加班單等上傳系統，分類、關聯、版本控管，重要文件不可任意刪除
財務收支 日常記帳 所有收入（工程請款、銷售）、支出（採購、人事、雜支）登錄系統 → 上傳憑證 → 分公司別、專案別
財務結算 月度損益 收入＋支出（含公司間往來）彙整 → 按公司別、專案別產出損益表 → 可匯出供會計師報帳

多公司隔離為本案架構核心約束：畫面可共用元件，但所有資料查詢／寫入必須強制帶公司識別條件；建議在 Service Layer 統一以 middleware 攔截，而非各功能自行檢查，避免遺漏造成跨公司資料誤查、誤改或錯帳（訪談十五、15.2 明確點出此風險）。

共 41 個功能模組（詳見 ⑩ 費用估算之階段分佈）。

主要資料流

  1. 工程接案到請款閉環 建立專案與階段設定 → 收定金 → 材料需求發出 → 施工進行＋每日回報 → 主管審核 → 達成階段條件 → 系統提醒請款 → 財務確認收款 → 解鎖下一階段（未收款則鎖定，需授權例外）→ 驗收結案

  2. 材料裁切餘料追蹤 原料入庫 → 依需求裁切 → 記錄實際使用量 → 剩餘量轉為餘料庫存（含規格、位置、可否再用）→ 下次需求優先比對可用餘料

  3. 雙公司財務隔離但可追溯 工程公司材料需求 → 材料公司內部交易 → 公司間往來紀錄（非一般外部銷售）→ 各自損益表獨立產出，但公司間往來可交叉核對

⑦ 安全性要點

身份驗證與授權 - JWT Token；管理者層級建議強制多因素驗證（訪談 10.2 明確要求） - RBAC 最小權限，權限矩陣須同時考慮「公司別」與「角色別」兩個維度

資料安全（訪談 10.2 逐項列出） - 傳輸加密（HTTPS）、資料庫加密、備份加密 - 操作稽核、異地備份、帳號停用、登入失敗次數限制 - 文件下載控管、資料匯出權限管控 - 定期還原演練

重要文件保護 - 合約、施工報告、薪資憑證等關鍵文件不可任意刪除，需版本保留機制
