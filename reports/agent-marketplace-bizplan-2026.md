# AI Agent 市場平台 企劃書
### 版本 v1.1 ｜ 2026 年 6 月（修訂版）

---

## 一、一句話定位

> **「讓企業 AI 能力可以像外包服務一樣媒合、交付、自動結算的協作市場」**
>
> 任何開發者或企業的 AI 系統缺少某種能力，都能到這個市場找到能做這件事的 agent，完成後由系統自動觸發結算費用。

> **定位說明**：口語上說「agent 互相付費」，精確機制是——雙方背後的開發者或企業預存點數，agent 執行任務時自動觸發扣款與結算。**在對外提案、投資人或客戶溝通中，請使用「AI 能力外包市場」或「agent 協作結算平台」的說法**，避免引發「agent 有沒有法人資格」「agent 怎麼開發票」等不必要的定位質疑。

---

## 二、為什麼現在是機會

### 市場現況

| 現有玩家 | 定位 | 缺口 |
|---------|------|------|
| Fetch.ai | 區塊鏈 + 去中心化 | 太技術、難上手，企業導入門檻高 |
| Google A2A | 協議標準，不是市場 | 只有接線規格，沒有媒合與結算平台 |
| LangChain Hub | 工具分享，不是交易 | 沒有結算機制、沒有媒合邏輯 |
| CrewAI | 自己建 agent 團隊 | 不支援跨組織協作 |
| Zapier / Make.com | 自動化工作流程 | 人工設定流程，不支援 agent 自主媒合 |

**以上玩家都未提供「企業能直接用的 agent 協作交易市場」，即開即用、自動媒合、自動結算。**

### 為什麼 2026 年是時間點

- AI agent 數量爆炸：全球活躍 AI agent 數量快速增長（保守估計已達百萬規模，各平台官方統計數字出入較大，建議提案時以「爆炸式增長」表述取代精確數字）
- 單一 agent 能力有限，協作需求開始出現
- Google A2A 協議（2025 年底推出）讓不同 agent 能互相溝通的技術問題已解決
- 企業開始問「我的 agent 能不能叫別人的 agent 幫忙做事」

## 三、核心概念說明

### 平台是什麼

想像這是一個「AI agent 版的 104 人力銀行」——

- **賣方（供給端）**：有特殊能力的 agent 開發者把自己的 agent 上架，標明能做什麼、費用多少
- **買方（需求端）**：有任務的 agent 或企業到平台找能力，下訂單、執行、付款
- **平台（你）**：負責媒合、驗收、結算、抽成

### 一次完整交易流程

```
1. 「客戶 agent」遇到自己做不到的任務
         ↓
2. 上平台搜尋有這個能力的「供應商 agent」
         ↓
3. 系統自動推薦 3 個候選 agent（依評分、價格、成功率排序）
         ↓
4. 發出任務 + 預付點數到平台（保管）
         ↓
5. 供應商 agent 執行任務
         ↓
6. 系統自動驗收（或雙方評分）
         ↓
7. 驗收通過 → 平台釋放點數給供應商（扣手續費）
```

## 四、商業模式

### 收入來源

| 收入類型 | 說明 | 費率 |
|---------|------|------|
| 平台手續費（早期） | Phase 1-2 吸引供應商冷啟動期 | **10%**（前 6 個月） |
| 平台手續費（成熟期） | Phase 3 起生態建立後調整 | **18-20%**（第 7 個月起） |
| 會員訂閱（供應商） | Verified 標章 + 優先曝光 | NT$1,500/月 |
| 會員訂閱（企業版） | 客製化媒合 + 優先客服 | NT$8,000/月起 |
| 加速審核 | 新 agent 快速上架審核 | NT$2,000/次 |

> **抽成策略說明**：Fiverr 收 20%、Upwork 收 5-20%，但它們已有成熟買賣方生態。早期平台直接收 20-25% 會讓供應商轉向自建或競品。建議前 6 個月以 10% 抽成換供應商黏著度，再靠交易數據與評分體系建立護城河後調整費率。

## 五、三階段執行計畫

### Phase 1 — 驗證市場（0-3 個月）

**目標**：找到 10 個願意付費的真實交易案例

**要做的事**

- [ ] 建立「能力登錄頁」：讓 agent 開發者填寫自己 agent 能做什麼
- [ ] 設計第一版媒合機制（人工 + 簡單系統）
- [ ] 建立點數系統（先用真實貨幣，不用代幣）
- [ ] 招募前 20 個供應商 agent（從你認識的開發者社群開始）
- [ ] 找前 5 個企業客戶來試用（從你現有客戶開始）

**成功門檻**：10 筆付費交易完成 ＋ 雙方都願意再來

**技術需求（最小可行）**

| 元件 | 工具 | 建置時間 |
|------|------|---------|
| 登錄表單 | Google Form 或 Notion | 1 天 |
| 媒合 | 人工配對（先不用系統） | 即時 |
| 結算 | 銀行轉帳 + 記帳 | 1 天 |
| 溝通 | Telegram 群組 | 即時 |

Phase 1 的核心原則：**先驗證需求，不要先建系統**

---

### Phase 2 — 建立平台（3-6 個月）

**目標**：讓交易可以不靠人工介入自動完成

**技術架構**

```
使用者介面（Next.js + Tailwind）
         ↓
API 服務層（FastAPI / Python）
         ↓
┌──────────────────────────────────┐
│  媒合引擎  │  點數系統  │  驗收引擎  │
└──────────────────────────────────┘
         ↓
資料庫（PostgreSQL + pgvector 向量搜尋）
         ↓
Agent 通訊（Google A2A 協議 SDK）
```

**核心功能清單**

| 功能 | 說明 | 優先級 |
|------|------|-------|
| Agent 能力頁 | 像商品頁一樣，顯示 agent 能做什麼 | P0 |
| 搜尋 + 篩選 | 依能力、價格、評分搜尋 | P0 |
| 點數充值 / 提領 | 買家充值，賣家提領，平台抽成 | P0 |
| **身份驗證 + API Key 管理** | **agent 呼叫時驗證身份，防冒充與重播攻擊** | **P0** |
| 任務追蹤 | 任務狀態、進度、紀錄 | P1 |
| 評分系統 | 完成後雙方評分 | P1 |
| **爭議仲裁機制** | **驗收有爭議時的人工審裁流程 + 退款規則** | **P1** |
| 自動驗收 | AI 判斷任務是否完成（需定義「完成」的結構化標準） | P2 |

> **驗收機制補充**：「AI 自動驗收」是整個商業模式最高風險點。Phase 2 建議先定義三種任務型態分別設計驗收規則：(1) 結構化輸出型（回傳 JSON / 報告）→ schema 驗證；(2) 生成型（文案、程式碼）→ 人工初審 + 買方確認；(3) 動作型（傳送郵件、更新資料庫）→ 副作用日誌 + 截圖。不要用一個通用 AI 判斷「任何任務算不算完成」。

**技術選型（現成工具，不需從零開始）**

- **A2A 協議**：Google 開源 SDK，agent 之間溝通的標準格式
- **MCP**：讓你的平台能被各種 AI 工具接入
- **pgvector**：做能力語意搜尋（「找能寫程式的 agent」自動匹配）

---

### Phase 3 — 規模化（6-12 個月）

**目標**：月交易額達 NT$100 萬，建立行業標準地位

**要做的事**

- 開放 API，讓第三方 AI 工具直接接入平台
- 建立「Verified Agent」認證體系（有公信力的評級）
- 考慮台灣以外市場（東南亞企業有類似需求）
- 評估鏈上結算可行性（如果規模夠大）

## 六、你的競爭優勢

### 為什麼你能做

| 優勢 | 說明 |
|------|------|
| 技術能力 | 你本來就在幫客戶建 AI 系統，懂 MCP、懂 agent 架構 |
| 客戶資源 | 現有客戶就是第一批需求方 |
| 開發者人脈 | 認識能上架 agent 的開發者 |
| 速度 | 中心化版本 6-8 週可上線，大廠動不了這麼快 |

### 護城河（跑起來後）

- **交易數據**：知道哪種能力最被需要、成功率多高
- **評分體系**：只有在你平台交易的 agent 才有評分紀錄
- **生態網絡效應**：供應商越多 → 買家越多 → 供應商還想來

## 七、風險與對策

| 風險 | 嚴重程度 | 對策 |
|------|---------|------|
| 冷啟動：沒人來 | 高 | 自己先上架 5 個 agent 當種子供給；早期降手續費至 10% 吸引供應商 |
| 驗收爭議：任務算不算完成 | 高 | Phase 1 全人工仲裁；按任務型態設計分類驗收規則，不要通用 AI 判斷 |
| 供應商 agent 品質差 | 中 | 先做邀請制，審核後才能上架；設 7 天觀察期 |
| 被大廠抄 | 中 | 快速建立交易數據與評分體系，這是壁壘；數據比技術更難複製 |
| **法律合規：代付費 / 發票 / 金流** | **高** | **預付點數模式必須符合電子支付法規；跨境交易需確認稅務義務；企業買家通常要求統一編號開立發票，需提前設計金流合規架構** |
| **資安：agent 身份偽造 / 惡意 payload** | **中** | **Phase 2 起強制 API Key + 請求簽章驗證；上架前對 agent 行為做沙箱測試** |
| 代幣問題 | 低（先不碰鏈） | Phase 1-2 用真實貨幣，不碰代幣 |

## 八、第一步：這週要做的三件事

1. **列出你現在有的 agent 能力清單**（哪些 agent 可以第一批上架）
2. **聯繫 3 個現有客戶**，問他們有沒有「希望 AI 幫忙做但現在做不到」的任務
3. **建一個 Google Form** 讓有興趣的開發者登記「我有什麼 agent 能力想上架」

## 十、總結

這個市場現在有技術（A2A 協議），有需求（agent 越來越多），缺的是**「讓這些 agent 能互相找到彼此、信任彼此、付錢給彼此」的平台**。

你有技術背景、有現有客戶、有開發者人脈——這是你能先跑起來的理由。

**最重要的一步不是建系統，是找到第一個願意付費的真實交易。**

## 十一、v1.1 修訂說明

本版針對以下五點進行修正：

1. **定位語言**：「agent 互相付費」改為「企業 AI 能力外包市場」，避免法人資格、發票等無謂質疑
2. **競品分析**：補入 Zapier / Make.com 作為間接競品，使競爭地圖更完整
3. **抽成策略**：冷啟動期（前 6 個月）降為 10%，換供應商黏著度，成熟後調回 18-20%
4. **驗收機制**：補充三種任務型態的分類驗收思路，明確指出「通用 AI 判斷」的高風險
5. **風險表**：新增法律合規（金流 / 發票）與資安（身份偽造）兩個原本空缺的高中風險項
