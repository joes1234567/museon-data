關鍵依賴說明

▸
L0 → 全部：角色權限 RBAC 和學年設定是所有模組的地基，不做就全部模組都要回頭改。
▸
P1 課程 → P2 財務：班級和出缺席資料建好，帳單才能正確計算出勤調整。
▸
P1 師資基礎 → P2 財務：排班和打卡資料是薪資計算的輸入來源。
▸
P1 課程 + P1 師資 → P3 師資進階：教師培訓和行為積分需要排班、課程資料作為計算基礎。
▸
P2 財務 + P1 課程 → P4 前台：家長 App 的出缺席查詢、帳單查看，需要 P1/P2 資料已建立。
▸
P1–P4 全部穩定 → P5 MUSEON 串接：MUSEON 讀取業務資料的 API 串接，需要四大模組資料已穩定累積，串接才有意義。
▸
MOD 24 知識庫 + P5 串接 + 學員資料累積 → P6 AI：AI 口說練習、客製出題、弱點分析都需要知識庫到位 + 足夠的學習歷程資料。MOD 24 越早啟動，P6 品質越高。
分期詳細規劃
P0 — 動工前提
系統底層建置
這不是「功能」，是所有功能的地基。不做 P0，後面每個模組都要回頭改架構。
強制條件： 無條件先做，不進業主取捨討論範圍。
🏗️
L0 系統底層 4 模組
MOD 14 — RBAC 角色權限管理 MOD 04 — 學年期別設定 MOD 02 — 分校基礎資料 MOD 01 — 人員資料管理（學生/家長/老師/員工一次建檔，含教職員 type 分流，學生永久 ID 跨學年不斷檔）
✓ P0 完成後交付
系統可登入、可設定角色權限、可定義學年期別、可管理分校資料。讓後續所有功能模組能正確「歸屬」的骨架。
P1 — 核心作業
內部核心業務跑起來 + 知識庫同步啟動
後台人員最常用的功能，讓教職員先熟悉系統，再開放家長端。知識庫同步建置越早，AI 品質越高。
依賴： P0 完成後才能開始。
📚
課程與教學 4 模組
MOD 03 — 課程與班級管理（多班並存、班名年度更新） ⚠️ 複雜節點 MOD 06 — 報名/就讀管理（一人多班，多對多關係） ⚠️ 複雜節點 MOD 08 — 出缺席管理 MOD 09 — 補課管理
👨‍🏫
師資與人資（基礎） 2 模組
MOD 02 — 分校與教室管理（四校區、排課衝突偵測） MOD 07 — 排課管理
📖
知識庫建置（MOD 24）（MUSEON 負責）— 同步啟動
歷史 QA 教材收集與整理 統一格式（題目/標準答案/難度標籤） 教學 wiki 建立 向量化供 P6 AI 查詢使用 MOD 24 越早啟動，P6 AI 口說與客製出題品質越高
✓ P1 完成後交付
後台人員可管理班級、排課、出缺席、補課。財務計算有資料來源。知識庫開始積累素材。這是系統「真實上線」的第一個里程碑。
P2 — 財務與安全合規
金流上線 + 法律風險消除
財務是業主最直接的 KPI；安全照顧是法律義務，發生事故後才補就太晚了。
依賴： P1 課程與排班資料需先建立，財務計算才能正確。
💰
財務 5 模組
MOD 10 — 定價/費用規則（五種費用 × 多折扣組合） ⚠️ 規則引擎複雜 MOD 11 — 帳單/繳費（部分繳款、暑期分期） ⚠️ 複雜節點 MOD 12 — 統一通知 Bus MOD 15 — 對帳/財務報表 MOD 16 — 薪資與打卡排班（跨校薪資攤算、鐘點費依班級人數計算） ⚠️ 最高複雜度
🏥
學生安全照顧 4 模組
MOD 29 — 學生健康與過敏紀錄 ⚠️ 安全責任，法律風險 MOD 27 — 吃藥管理（含家長授權書、服藥執行紀錄） ⚠️ 安全責任，法律風險 MOD 30 — 接送授權管理（長期授權 + 臨時委託） MOD 31 — 家長同意書管理（電子簽署）
✓ P2 完成後交付
帳單可開、收費可追蹤、薪資可自動計算。學生健康、用藥、接送授權全部數位化，法律風險降低，可應對外部查核。
P3 — 深化內部
招生、行政、師資進階
P1/P2 穩了之後，開始補強招生轉換效率、行政流程、以及教師培養體系。各子單位可分批導入，不需同時。
依賴： P1 + P2 穩定運行後開始。各子單位可分批導入，不需同時啟動。
🎯
招生與 CRM 2 模組
MOD 05 — 試聽/諮詢管理（含預約子模組：官網/LINE/App 入口、可選時段、到場/未到紀錄、來源追蹤） MOD 18 — 招生/行銷追蹤（含潛在客戶 CRM：新名單→已聯絡→已預約→已試聽→已入班/未成交，支援離校生回流）
🗂️
行政 5 模組
MOD 13 — 餐點代訂（儲值金預充、老師確認才扣款、請假自動不扣） MOD 26 — 活動管理（建立/報名/名額控管/QR Code 電子報到） MOD 28 — 補課影片管理（自動比對缺席名單分發影片） MOD 32 — 教材發放紀錄 MOD 17 — 學習歷程/成績（含家長一對一會談子模組：老師開放時段/家長預約/系統自動產製會談前摘要/會談後追蹤）
🎓
師資進階培訓 3 模組
MOD 33 — 外師管理（外籍老師工作證效期追蹤 / 外聘兼職勞健保門檻，type 欄位分流） ⚠️ 雙類型設計 MOD 34 — 教師培訓管理（SOP/培訓影片/測驗/申論/主管審核/能力紀錄/新人 onboarding） MOD 35 — 教師行為積分系統（每日任務五感恩 + 會議出席QRCode + 能量存摺積分連動獎金，共用 teacher_activity_log） ⚠️ 三合一設計
✓ P3 完成後交付
招生有 CRM 可追名單；行政流程數位化；教師新人有系統化 onboarding、每日行為有積分記錄。內部管理完整閉環。
P4 — 對外前台
家長（學生）/ 教職人員 App + 行銷
內部系統穩了，再開放對外介面。這樣家長看到的是可信賴的系統，不是半成品。
依賴： P1 課程資料 + P2 財務帳單 全部到位後再開。P5 AI 推播功能在 P6 接通後加入。
📱
家長（學生）/ 教職人員前台 1 模組
MOD 23 — 家長（學生）/ 教職人員 App（雙角色）：家長端（含學生）查成績/出席/帳單/通知/搜尋/對話式留言（類LINE，客訴標記，主管可見高風險訊息），學生在家長帳號下看課程/作業/補課影片/AI 口說；教職人員端課表查詢/班級出席管理/學生資料快查/通知推送/吃藥確認執行紀錄
✓ P4 完成後交付
家長有 App 可查出缺席、帳單、通知、跟老師對話；學生有入口接補課影片。系統完整對外開放，形成完整服務閉環。P6 AI 推播功能待接通後加入。
P5 — MUSEON 智能對接
四大模組 API 串接，讓 AI 讀得到業務資料
透過營運系統開放 API，MUSEON 可讀取四大業務模組即時資料，提供主管問答、異常預警與跨部門報告整合。資料仍由營運系統管理，MUSEON 負責讀取與智能分析。
依賴： P1–P4 全部穩定運行後啟動。API 串接需要各模組資料已有足夠積累才有分析意義。
🔌
MUSEON API 串接 4 個 API 模組
API 01 — 行政模組串接（學生建檔/出缺席/報名就讀，支援行政流程智能提醒） API 02 — 總務模組串接（場地排課/設備管理，回答「哪間教室今天有空」） API 03 — 客服模組串接（家長詢問紀錄/投訴處理，輔助快速查詢學生狀態） API 04 — 行銷模組串接（說明會報名/招生來源/活動成效，自動產製招生分析報告）
🔐
權限與安全架構
MUSEON_SVC 獨立服務帳號（不借用員工帳號，日誌格式「MUSEON_SVC 執行◯◯，觸發者：員工」） 最小權限原則：生效權限 = min（MUSEON 權限, 員工權限） 身份綁定：LINE ID ↔ 員工編號，一次性完成 高風險操作人工確認（改費率/軟刪除先推播確認） 自動排程操作鎖定白名單低風險項目
✓ P5 完成後交付
MUSEON 可即時回答業務問題（「這個孩子還有幾堂補課」「本月未繳費名單」），主動偵測異常（連續缺席/帳單逾期/老師鐘點超時），自動產製跨部門報告。
P6 — AI 智慧輔助
資料積累後啟動，從被動查詢到主動預警
MOD 24 知識庫 + P5 串接 + 學員資料積累三個前提同時到位後，才能發揮 AI 最大效益。前提越早準備，P6 越快啟動。
依賴： MOD 24 知識庫建置到位 + P5 MUSEON API 串接完成 + 學員學習歷程資料足夠積累（至少一學期）。
🤖
AI 智慧輔助 5 個 AI 模組
MOD 19 — AI 學習助理（MUSEON 負責）：個人化學習建議/出席異常預警/學習里程碑通報/繳費到期提醒/每週進度摘要，主動推播家長不需問 MOD 20 — AI 作業批改（營運系統內建）：AI 初評 + 老師最終審核，大幅縮短批改時間 MOD 21 — AI 口說練習（營運系統內建）：學生與 AI 對話練習英文，評估發音/流暢度/進步軌跡 ⚠️ Demo 為簽約前提，先行驗證可行性 MOD 22 — AI 行政檢查（MUSEON 負責）：每日自動掃描異常（欠費未通知/出缺席異常/補課逾期），主動提醒行政 MOD 25 — AI 客製出題與弱點分析（MUSEON 負責）：根據學員歷史識別弱點，生成個人化練習題，老師審核後發送
✓ P6 完成後交付
AI 從「被動查詢工具」進化為「主動預警系統」——學生弱點自動分析、家長不需追問、行政異常自動發現。系統完整實現從招生到學習成果的數位閉環。
完整系統總覽（39 個模組）
L0 底層 4 個 → P1 核心 6 個（含 MOD 24 知識庫）→ P2 財務+安全 9 個 → P3 深化內部 10 個 → P4 對外前台 1 個 → P5 API 串接 4 個 → P6 AI 輔助 5 個

業主決策框架：P0–P2 是必做核心（19 個模組）；P3–P4 各子單位可由業主排序；P5–P6 依業主數位化成熟度推進，不影響 P1–P4 的正常上線。
MOD 24 知識庫建議在 P1 就同步啟動——它是 P6 AI 品質的前置條件，越早啟動等於為未來 AI 儲值。
