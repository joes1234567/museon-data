關鍵依賴說明

▸
L0 → 全部：角色權限 RBAC 和學年設定是所有模組的地基，不做就全部模組都要回頭改。
▸
P1 課程 → P2 財務：班級和出缺席資料建好，帳單才能正確計算出勤調整。
▸
P1 師資基礎 → P2 財務：排班和打卡資料是薪資計算的輸入來源。
▸
P1 課程 + P1 師資 → P3 師資進階：教師培訓和行為積分需要排班、課程資料作為計算基礎。
▸
P2 財務 + P1 課程 → P4 前台：家長 App 的出缺席查詢、帳單查看，需要 P1/P2 資料已建立。
分期詳細規劃
P0 — 動工前提
系統底層建置
這不是「功能」，是所有功能的地基。不做 P0，後面每個模組都要回頭改架構。
強制條件： 無條件先做，不進業主取捨討論範圍。
🏗️
L0 系統底層
RBAC 角色權限管理 學年期別設定 學生永久 ID 分校基礎資料 多校區關聯設計
✓ P0 完成後交付
系統可登入、可設定角色、可定義學年期別、可管理分校資料。這是讓後續所有功能模組能正確「歸屬」的骨架。
P1 — 核心作業
內部核心業務跑起來
後台人員最常用的功能，讓教職員先熟悉系統，再開放家長端。
依賴： P0 完成後才能開始。
📚
課程與教學
班級管理（多班並存） 排課系統 出缺席紀錄 學生多班歸屬設計
👨‍🏫
師資與人資（基礎）
教職員建檔（正職/外籍/外聘兼職 type 分流） 排班系統 打卡紀錄 外籍老師合規（工作證效期追蹤） 外聘兼職勞健保門檻計算
✓ P1 完成後交付
後台人員可管理班級、排課、出缺席、打卡。財務計算有資料來源。這是系統「真實上線」的第一個里程碑。
P2 — 財務與安全合規
金流上線 + 法律風險消除
財務是業主最直接的 KPI；安全照顧是法律義務，發生事故後才補就太晚了。
依賴： P1 課程與排班資料需先建立，財務計算才能正確。
💰
財務
帳單產生與收費 繳費紀錄與對帳 學費優惠/折抵規則 跨校薪資計算 鐘點費申報
🏥
學生安全照顧
學生健康與過敏紀錄 吃藥管理（含家長授權書） 接送授權紀錄 家長同意書管理
✓ P2 完成後交付
帳單可開、收費可追蹤、薪資可計算。學生健康與用藥紀錄數位化，法律風險降低，可應對外部查核。
P3 — 深化內部
招生、行政、師資進階
P1/P2 穩了之後，開始補強招生轉換效率、行政流程、以及教師培養體系。
依賴： P1 + P2 穩定運行後開始。各子單位可分批導入，不需同時。
🎯
招生與 CRM
潛在客戶 CRM（名單到入班狀態流） 預約系統（參觀/試聽/諮詢/會談） 試聽與諮詢管理 說明會報名 轉介來源追蹤
🗂️
行政
教材發放紀錄 文件管理 活動管理與報名 場地設備管理
🎓
師資進階培訓
教師培訓系統（SOP/影片/測驗/申論/主管審核） 教師行為積分系統（每日任務/五感恩/會議出席 QR Code/能量存摺） 底層共用 teacher_activity_log 資料表 積分與獎金連動
✓ P3 完成後交付
招生有 CRM 可追名單；行政流程數位化；教師新人有系統化 onboarding、每日行為有積分記錄。內部管理完整閉環。
P4 — 對外前台
家長/學生端 + 行銷
內部系統穩了，再開放對外介面。這樣家長看到的是可信賴的系統，不是半成品。
依賴： P1 課程資料 + P2 財務帳單 + P3 招生資料 全部到位後再開。
📱
家長/學生前台
家長 App（出缺席/帳單/通知/搜尋/對話留言） 學生 App（課程/作業/補課影片/AI 口說練習） 通知系統（班級公告/繳費提醒/活動） 家長一對一會談管理
📣
行銷
口碑來源追蹤 說明會/活動報名 對外知識庫（官網內容）
✓ P4 完成後交付
家長有 App 可查出缺席、帳單、通知、跟老師對話；學生有入口接補課影片和 AI 練習。系統完整對外開放，形成完整服務閉環。
AI 智能層：不是獨立導入期，而是橫切的加值能力，隨各單位漸進接入—— 課程單位接入 AI 口說練習；師資培訓單位接入 AI 測驗出題；家長前台接入 AI 留言分類與主管預警；師資積分系統接入 AI 回報內容品質檢查。 不需等到 P4 才有 AI，P1 起就可以局部接入。
