4
我補充的四個缺口
你列的三項是「能力」，這四項是「能力一旦有了會捅出的洞」——沒有它們，行銷分身會比不做更危險
① 發布前人審 Gate（最優先，不能跳過）

CLAUDE.md 對 GitHub Pages 發布有硬規則「禁止即興操作，必須用 publish-report.sh」——同樣的紀律要套用在社群發文上，而且風險更高：報告發錯頂多內部尷尬，貼文發錯是直接曝光給客戶。行銷分身不該有「自動發布」這個按鈕，只該有「產出草稿 + 通知人審核」。這也是 SafetyAnchor「不奪權」在這個場景的具體落地。

② 成效回饋迴圈

IG/FB Insights API 的數據要真的流回 ad-pilot／business-12，形成「發文 → 數據 → 診斷 → 下一版腳本」的閉環。沒有這條線，行銷分身只是一台發文機器，不會變聰明——這正是北極星「自我迭代」維度該接通的地方，不接就是又一個 5/7 卡住的例子。

③ 素材／版權合法性檢查

影片管線一旦自動化產出，素材來源（圖庫、音樂、字型）的授權範圍要有人把關，不然自動化規模一放大，侵權風險也跟著放大——手動剪片時這件事靠人的常識擋著，自動化之後這個常識必須變成一道明確檢查。

④ 輿情/危機監控與自動暫停

一旦有排程自動發文的能力，就要有機制偵測留言區負評、公關風險訊號，達門檻自動暫停後續排程並通知人——這是北極星「自我修復」延伸到對外溝通的版本：不是修 bug，是止住正在發生的品牌傷害。

分階段路線圖
故意把「人審 Gate」放在 Phase 1 最前面，不是最後——順序本身就是風險控管
1
Phase 1 · 地基與煞車
先把煞車裝好，再談油門
  • 建立發布前人審 Gate（草稿產出 → 通知 → 人工核准才發）
  • 把 instagram_post 從 stub 換成真實 Meta Graph API 呼叫，但預設只能產草稿，不能直接發
  • Whisper 真的 pip install + enable，跑通一次端到端字幕轉錄當驗收
2
Phase 2 · 策略串接
先讓 MUSEON 出腳本跟文案，影片還是人工剪
  • 串 video-strategy → script-optimizer → brand-builder 成一條行銷 skill chain
  • 以 workflow-svc-brand-marketing 現成骨架起步，不重建
  • 驗收標準：一週內產出可用的貼文文案＋短影音腳本，人工剪輯後手動發布
3
Phase 3 · 影片自動化
接上 FFmpeg／Remotion，產出成品草稿
  • 建置素材/版權合法性檢查，作為影片產出前置閘門
  • Remotion 套版型（口播字卡、品牌片頭片尾）先跑通一種格式
  • 產出仍進 Phase 1 的人審 Gate，不因為「自動化了」就跳過
4
Phase 4 · 回饋迴圈與監控
讓分身開始自己變聰明
  • IG/FB Insights 數據回灌 ad-pilot／business-12
  • 建立輿情監控 + 自動暫停排程機制
  • 七武海「自我迭代」維度正式接通這條線
