# Agent 市場可行方案報告

> 製作日期：2026-06-27
> 目標：建立 AI Agent 互相協作、發包接案的市場平台

---

## 這是什麼？

想像一個「AI 版的 104 人力銀行」——

但不是人找工作，是 **AI agent 找任務、接任務、完成後收費**。

當一個 AI agent 遇到自己不會的事，它可以去這個市場「外包」給專門的 agent 幫忙，完成後自動付費結算。

**你的角色：** 這個市場的平台主，賺每筆交易的手續費。

---

## 市場現況

這個領域現在**有人在做，但還沒有霸主**。

| 現有競爭者 | 規模 | 問題 |
|---|---|---|
| Fetch.ai（美國） | 270 萬個 agent | 太技術、偏幣圈，一般企業看不懂 |
| Google A2A | 協議標準，150+ 組織用 | 只是溝通協議，沒有市場平台 |
| Agentverse | 早期 | 介面複雜，不適合非工程師 |

**你的切入點：企業實用版**——不用懂區塊鏈，不用懂幣，就能讓 AI agent 幫公司接工作、省成本。

---

## 建議路線（三個階段）

### 第一階段：先驗證有沒有市場（6-8 週）

目標很簡單：**有沒有人願意賣能力？有沒有人願意付錢買？**

做四件事：

**1. Agent 上架頁**
- 開發者可以登錄他們的 agent，寫清楚「這個 agent 能做什麼」
- 照 Google A2A 的格式（已有標準，直接套）

**2. 任務媒合**
- 有人發任務 → 系統自動找能力符合的 agent → 推薦配對

**3. 點數結算**
- 買家買點數 → 任務完成扣點 → 開發者月底換現金
- 你抽 20-30% 手續費

**4. 驗收 + 仲裁**
- 任務完成後雙方評分
- 有爭議你來判

**工具（可直接用，不用從零造）：**
- 後端：FastAPI（你們本來就是 Python，直接上）
- 前端：Next.js（2-3 週出介面）
- Agent 通訊：Google A2A SDK（開源免費）
- 資料庫：PostgreSQL
- 部署：Railway 或 Fly.io（月費 $5-30 美元）

---

### 第二階段：建立信任機制（上線後 3 個月）

解決「怎麼知道這個 agent 真的會做？」的問題：

- **能力驗測**：平台自動發測試任務，算通過率，顯示在 agent 頁面
- **信譽評分**：每完成一筆任務就累積評分（類似 Uber 評分）
- **認證徽章**：你人工審核，頂級 agent 給 Verified 標記

---

### 第三階段：考慮區塊鏈結算（有真需求再做）

如果：
- 點數系統遇到法規問題
- 客戶要求「不經過任何中間人」的透明結算

再評估用智能合約。

**Fetch.ai 也是先做了中心化版本，走了 3 年才慢慢遷移——不要一開始就碰。**

---

## 為什麼建議先做「中心化版」而不是直接上區塊鏈？

| | 中心化版（先做） | 區塊鏈版（之後考慮） |
|---|---|---|
| 開發速度 | 6-8 週可上線 | 至少半年 |
| 驗收問題 | 你來判，靈活 | 誰判？程式判不了主觀任務 |
| 用戶友善度 | 一般人能用 | 要懂錢包、幣，門檻高 |
| 法規風險 | 低 | 幣的法規還很亂 |
| 先驗證市場 | 可以 | 做了才知道沒需求，損失大 |

## 最關鍵的一個問題

> **第一批賣家（agent 開發者）從哪裡來？**

市場最難的不是技術，是「先有供給還是先有需求」。

**選項 A：自己先上架**
你們自己做的 agent 先上，找 3-5 個客戶來試用，驗完驗收邏輯才開放第三方。
- 優點：風險最低，你最了解自己的 agent 能做什麼
- 建議：如果你們手上有現成 agent（查公司資料、寫話術、自動回覆等），這條路最快

**選項 B：先招募開發者**
找 5-10 個 agent 開發者進來供貨，你幫他們找第一批客戶。
- 優點：產品多樣，更像真正的市場
- 缺點：需要先建社群，花時間

**建議：先走 A 路，驗證完再開 B 路。**
