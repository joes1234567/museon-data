擺渡人文蔬食料理 — 系統需求訪談會議記錄

📅 日期：2026-06-10 👥 參與者：J（四維，系統顧問）、云亭（餐廳管理員） 📝 記錄形式：語音轉寫整理

一、會議背景

徐主任（餐廳老闆）透過白老師補習班系統合作，提出希望導入餐廳系統的需求。J 代表四維公司與云亭進行需求訪談，釐清實際狀況與可行範疇。

二、現況確認

項目現況
現有 POS 系統ICF（已使用數年，員工熟悉，1 個月可上手）
月費支出約 NT$3,000+；含 LINE Pay/刷卡約 NT$6,000/月
帳務處理全人工，半個月處理一次，月結報表給股東
排班方式外場 Excel、內場手寫，ICF 有打卡功能
進銷存無系統，食材成本全人工計算，誤差高
行銷已有專職人員負責拍片發文
新店規劃預計 11 月遷入新地點（1F 兩個店面 + 2F 宴會廳 + 3F 另一部門）

部門結構（新地點）

  • 1F：餐廳 + 吉拿棒（兩台 POS 分開結帳）
  • 2F：宴會廳
  • 3F：枋寮（業態待確認）

三、核心討論與共識

3.1 徐主任原始需求 vs 實際可行性

主任提出的需求云亭評估結論
全面取代 ICF（點餐 + 後台）高風險，開店期同時換系統 = 天下大亂不建議，v1 不做
導入 AI 數位員工單店規模，工讀生即可替代，ROI 不足暫緩，多店後再評估
送餐機器人動線不符，與人文禪風定位違和不建議
後台會計優化明確痛點，人工作帳耗時且誤差多✅ v1 優先做
進銷存 / 食材成本計算明確痛點，目前完全沒有系統✅ v1 優先做
排班電子化現況散落 Excel + 手寫，整合需求明確✅ v1 優先做

3.2 雙方共識結論

  1. v1 範圍：後台管理系統（會計 + 進銷存 + 排班），不動 ICF
  2. 資料橋接方式：從 ICF 匯出 CSV 後手動上傳，不串 API
  3. 部門分帳：餐廳 / 吉拿棒 / 宴會廳各自獨立損益
  4. AI 數位員工：系統建置後期才評估，不在 v1 範圍
  5. 導入策略：先穩定內部（後台系統），再評估對外（線上點餐/訂位）

3.3 主要操作者

云亭——店內所有電腦相關事務唯一負責人，系統主要操作者。

四、風險提示

⚠️ 云亭特別要求納入報告

主任是視覺型決策者，單純介紹功能他會覺得「看起來都很棒為什麼不用」，需要清楚的風險對比才能讓他理解不可行性。

主要風險點

  • 11 月前換地點＋換系統＋員工學習 = 三重壓力
  • 客製系統買斷後仍有第三方服務月費（如支付、掃碼點餐），未必比 ICF 便宜
  • ICF 已有數年資料，移轉需驗證，有資料風險
  • 餐廳員工電腦程度偏低，學習新系統需時間

五、行動項目

項目負責人時間
產出系統規劃報告（含風險評估、費用估算）J（四維）禮拜日前
報告先交云亭，不直接給徐主任J—
云亭與店長內部對齊口徑後，再呈報主任云亭 + 店長—
週五遇到徐主任時的回應口徑J禮拜五

週五遇到徐主任的標準回應

「餐廳系統比較複雜，正在整理相關資訊和評估，過幾天會提供給餐廳那邊。」

六、後續評估項目（v2）

  • ICF 加購線上掃碼點餐、線上訂位功能（成本較低，不需客製）
  • 新店穩定 6 個月後，重新評估是否需要取代 ICF
  • 多店擴張時再評估 AI 數位員工的導入必要性
