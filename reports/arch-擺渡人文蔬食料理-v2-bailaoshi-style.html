① 專案摘要

為擺渡人文蔬食料理建立後台管理系統，解決帳務手工耗時、食材成本難追蹤、排班散落 Excel 三大痛點，並為未來線上點餐/訂位預留擴充接口。

使用者角色

角色描述主要操作
後台管理員（云亭）系統唯一主要操作者所有後台功能
店長查閱報表、審核資料報表、審批
老闆/股東月報查看報表輸出
員工班表確認查看班表（唯讀）

目標與範圍邊界

  • ✅ 在範圍內：後台帳務、進銷存、排班、ICF 資料橋接、部門損益分離
  • ✅ 在範圍內：多部門帳號分開（餐廳 / 吉拿棒 / 宴會廳）
  • ❌ 不在此次範圍：取代 ICF 點餐系統（v1 不做）
  • ❌ 不在此次範圍：線上掃碼點餐、線上訂位（v2 評估）
  • ❌ 不在此次範圍：AI 數位員工（現階段規模不需要）
  • ❌ 不在此次範圍：多公司整合架構（聚焦單一餐廳，未來擴張再評估）
  • ❌ 不在此次範圍：稅務試算（記帳系統範疇，非會計申報系統）

規模假設（可被推翻）

  • 日常操作人數：1–3 人
  • 每日交易筆數：< 500 筆
  • 員工人數：10–30 人
  • 部門數：3（餐廳 / 吉拿棒 / 宴會廳）
  • 資料量：輕量級，不需分散式架構

② 功能需求

User Stories

後台管理員（云亭）

  • 身為管理員，我需要從 ICF 匯入銷售數據，以便不用重複 key 資料
  • 身為管理員，我需要錄入每日進貨與費用，以便計算當日真實成本
  • 身為管理員，我需要按部門查看損益，以便釐清餐廳與吉拿棒分別賺賠多少
  • 身為管理員，我需要設定員工班表，以便取代現有 Excel 排班
  • 身為管理員，我需要匯入 ICF 打卡記錄，以便計算出勤與薪資
  • 身為管理員，我需要產出月結報表，以便每月交給股東查閱
  • 身為管理員，我需要查看食材消耗排行，以便找出高成本食材

店長

  • 身為店長，我需要查看每日/每週銷售摘要，以便掌握營運狀況
  • 身為店長，我需要審核班表，以便確認人力配置合理

老闆/股東

  • 身為股東，我需要匯出月度損益報表（PDF/Excel），以便定期審閱財務

②+ 系統功能清單（核心 / 加值）

以下功能全數納入本次建置範圍，依交付順序分為兩層。

🟢 核心功能層 Phase 1 交付
  • ICF 銷售數據匯入（每日結帳核心）
  • 部門分帳會計（餐廳 / 吉拿棒 / 宴會廳）
  • 費用錄入與月結報表
  • 食材進貨與成本計算（BOM 對應）
  • 排班管理（取代 Excel 班表）
  • 出勤匯入與薪資計算
  • 相關報表輸出（損益 / 出勤 / 成本 Excel 匯出）
  • MUSEON AI 智能助理（基礎配置）
🟡 加值功能層 Phase 2 交付
  • LINE 班表通知（讓員工收到班表推播）
    ⚠️ LINE Bot 月費說明：LINE Notify 已於 2025 年停用。目前需申請 LINE Bot，月費約 NT$200–800（依訊息量計費，一般用量約 200 元）。
  • 低庫存預警（食材低於閾值自動提示）
  • 加班費自動計算（出勤差異比對班表）
  • 相關報表輸出（損益、成本、出勤等整合報表）
  • 第三方支付費用記錄（LINE Pay / 信用卡手續費自動拆帳入費用分錄）
💳 第三方支付月費說明：現行透過 ICF 收取 LINE Pay 及信用卡付款，手續費約為交易金額 1.5%，每月約 NT$2,000–3,000（依實際刷卡量浮動）。此費用由 ICF 代扣，建議系統自動將此項列入每月費用分錄，供損益表呈現。

主要資料流

  1. 每日結帳流程
    ICF 匯出 CSV → 管理員上傳 → 匯入服務解析 → 寫入收入模組 → 自動分配到各部門帳
  2. 食材成本追蹤
    銷售數據 → 對應菜單 BOM → 計算食材消耗 → 更新庫存 → 產出成本差異報告
  3. 月結報表
    收入（ICF 匯入）+ 費用（手動錄入 + 第三方支付手續費）+ 薪資（打卡計算）→ 損益表 → PDF/Excel 輸出

⑦ 安全性要點

身份驗證

  • JWT Token（登入有效期 8 小時，適合餐廳班次）
  • 密碼 bcrypt hash 儲存

權限模型（RBAC）

角色權限
admin（云亭）全功能讀寫
manager（店長）報表讀取、班表審核、費用審核
owner（股東）報表讀取（唯讀）
staff（員工）個人班表查看（唯讀）

稽核要求

  • 所有資料變更記錄操作者與時間戳
  • 已鎖定月報不可修改（防止事後竄改帳務）
  • 匯入批次保留原始 CSV 檔案

資料安全

  • HTTPS 強制（Let's Encrypt 或自購憑證）
  • 不儲存 ICF 系統帳密（CSV 手動匯出方式，不串 API）
  • 員工薪資資料限 admin/manager 存取

⑨ v1 優先範圍 vs 先不做

v1 必做（目標：11 月前可用）

  1. ICF 銷售數據匯入 — 每日結帳核心，解決重複 key 資料問題
  2. 部門分帳會計 — 餐廳 vs 吉拿棒 vs 宴會廳分開損益
  3. 費用錄入與月結報表 — 取代手工 Excel 帳務
  4. 食材成本計算 — 進貨錄入 + ICF 銷售對應 → 自動計算食材消耗成本
  5. 排班管理 — 電子化班表，取代手寫 + Excel
  6. 出勤匯入 — 從 ICF 打卡記錄計算出勤
  7. 相關報表輸出 — 損益 / 出勤 / 成本等 Excel 格式供店長、股東查閱

v1 先不做（理由）

功能理由
取代 ICF 點餐系統換地點同期切換 POS，風險極高；ICF 已穩定運作，月費 NT$3,000 合理
線上掃碼點餐需串接第三方支付，增加月費成本；建議 ICF 加購此功能（已有此模組）
線上訂位同上，非緊急痛點
AI 數位員工單店規模，ROI 不足；未來多店擴張時再評估
送餐機器人空間動線不符，與餐廳人文禪風定位衝突
稅務試算輔助屬會計系統範疇；本系統定位為記帳系統，稅務申報由會計師處理，不在建置範圍
多公司整合架構目前聚焦單一餐廳（擺渡），待未來業務擴張至多點後再評估

v2 預期（新店穩定後 3–6 個月）

  • 評估是否以客製系統取代 ICF（需完整成本效益試算）
  • 線上訂位串接

⑩ 風險評估與建議

⚠️ 此段為核心參考內容，建議向徐主任說明時重點呈現

方案 A：維持 ICF + 新增後台系統（本文件建議方案）

面向評估
導入風險低 — 點餐系統不動，後台系統獨立上線，互不影響
上線時程可控 — 後台系統 2–3 個月可完成 v1
員工學習成本低 — 點餐流程不變，只有管理員需學新後台
月費ICF 約 NT$6,000/月（含第三方支付）+ 新系統主機費約 NT$1,000–2,000/月
開新店時後台系統可直接延伸，資料已在同一平台
主要風險兩套系統並存，ICF 銷售資料需定期手動匯出（每日或週期性）

方案 B：完整取代 ICF（不建議，尤其在新店開幕前）

面向評估
導入風險高 — 同期換系統、換地點，雙重混亂
上線時程11 月前完成完整系統極具挑戰，任何延遲影響開業
員工學習成本高 — 現場員工電腦程度偏低，1 個月學習期保守估計
月費客製系統維護費 + 第三方支付費，加總未必比 ICF 便宜
主要風險開幕期間系統不穩定 → 直接影響來客體驗與收入
資料風險ICF 數年累積資料移轉，需完整比對驗證
建議結論：採方案 A — 先建後台（會計 + 進銷存 + 排班），維持 ICF 點餐系統不動。待新店穩定營運 6 個月後，再評估是否有換 POS 的必要性。
